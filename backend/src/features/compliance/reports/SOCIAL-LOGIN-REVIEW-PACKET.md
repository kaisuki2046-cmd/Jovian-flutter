# 微信与 QQ Android 登录申请包

核对日期为 2026-11-22。用途为 Android 首发的移动应用登录申请准备。申请、平台能力审批和真机可用情况见[交接台账](LOGIN-APPLICATION-MATERIALS.md)。

## 可带入表单的业务和用途说明

> 这款 Android 应用提供命理排盘、周期运势、双人合盘和面向具体问题的算事功能，部分解读由 AI 辅助生成。申请第三方登录的用途是让用户从登录页主动选择微信或 QQ，通过平台授权建立或恢复本应用的账号会话。用户已保存的数据从本应用账户读取。申请权限以账号识别和实际使用的资料为限。

提交前以最终产品是否保留各功能核对这段介绍。微信表单只填微信用途，QQ 表单只填 QQ 用途。若申请昵称、头像等额外资料，分别写明是否必要、如何使用和是否保存。界面只展示已启用的授权途径，按真实可用方式提供替代入口。

## 测试证据的记录顺序

1. 打开带正式签名的候选包，检查隐私入口和第三方清单。用户点选微信或 QQ 后进入对应平台授权，能主动取消。
2. 通过官方流程登录后回到原 App。验证服务端核对身份后才建立会话、首次与再次登录的账号归属、授权拒绝、凭证过期、SDK 或平台不可达。
3. 按已实现的产品界面验证退出、授权撤回、解绑和注销。控制台各阶段的状态、候选包标识和脱敏证据登记在[交接台账](LOGIN-APPLICATION-MATERIALS.md)。AppSecret、AppKey、证书私钥、真实账号、访问令牌和验证码通过受控渠道配置。

当前可核实的本地实现会加载[虚拟身份适配器](../../account/server/auth-provider.mjs)，用模拟身份跑通开发流程。正式登录需要原生 SDK、平台配置、真实身份校验和对应审核状态。具体候选文件见[接线要求](LOGIN-APPLICATION-CHANGE-REQUIREMENTS.md)。

### 本地包与第三方披露的已核证据

- 已检查 `0.1.1` 测试 APK 的合并 Manifest 和 DEX，未检出微信 OpenSDK 或 QQ 互联的原生入口和常用类标识。两者登记为待接入；以日后正式依赖版本和安装包的实际行为更新状态。该包的校验值见 [Android 首发清单](ANDROID-RELEASE-CHECKLIST.md#已核对的内部-apk)。
- QQ 互联 SDK 声明所列运营者是**深圳市腾讯计算机系统有限公司**。其声明列有设备型号等用于 SDK 上报和排错的数据，也区分了分享、加好友等具体用途。首发仅申请登录时，只按选定版本和登录路径核定字段。接入验收需检查同意前无相关数据处理，明确拒绝后也不初始化对应能力，并按所选版本调用其隐私授权接口。 [QQ SDK 隐私保护声明](https://wiki.connect.qq.com/qq互联sdk隐私保护声明/) · [Android SDK 变更历史](https://wiki.connect.qq.com/android_sdk历史变更/)
- 微信 OpenSDK 的实际版本、接收方和 Android 登录资料范围，仍需从该应用控制台及官方 SDK 声明核定。独立记录微信资料和真机证据；QQ 的披露范围不能用于微信。
