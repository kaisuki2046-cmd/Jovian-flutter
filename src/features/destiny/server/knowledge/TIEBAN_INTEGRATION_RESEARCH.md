## 几条流程不能混成一个选条算法

- **包内默认分类取模**：`起数法.md` 第六至九节明确说明，各分类偏移是技能包约定、可以调整的常量。以 `(key + offset) mod pool.length` 选条，确定可复现并不代表对应命主事实。流年分类另按年龄过滤再取模。不能把默认偏移的输出认作经核定的预测依据。
- **人生事实回填**：`tieban.py` 可按已知父母、兄弟、配偶、子女等事实查表，另有按事业性情关键词选条的软锚。回填命中的文字不能作为另一条独立证据，再用于“验证”同一已知事实。按分类各自反推偏移，也不等于验证一个共同考刻尺度。
- **考刻定分表**：`kaoke.py` 依父母／兄弟实况锁定刻，再依婚姻／子女实况锁定分。源码注明秘数 1327 来自另一版本，个别 OCR 表格格局仍有未能确定的读法。只有出生四柱和性别，无法代替这套确认过程。
- **原书演算**：`yansuan.py` 包含太玄、皇极、河洛、日柱配卦等多法及不同例子。脚本自检可以验证其内部算术；尚未对原页、版本选择和最终条号适用性完成独立核验，不能据此把多法产生的全部编号合并当成选定条文。
- **十四表流年**：脚本自述需要求测时柱；缺失时回退到出生时柱属于近似。其本命分支未实现。它与现有 JSON 条文以及独立 CSV 版的条号对应，也需逐项核对，不能在接口中静默借用另一版文本。

这些是对提供包及源码的核对结果，不是为其中传统方法的有效性背书。原始包的自述与独立验证结果分别记录。

## 太玄基数接入

报告从本命排盘的四柱和已确认性别复算太玄基数。算法依据资料包 `references/演算法式.md` 第 1 节及 `scripts/yansuan.py` 的两项正卦起数。年月分别配数后除八取余，日时分别取个位，按照对应的八卦数化卦，再由上卦和互卦合成编号。中宫寄卦和加六满十的边界沿用该参考实现。资料包算例庚寅、甲申、丙午、甲午得到先天 3788 和后天 2664，两个编号都已通过原生排盘和 SQLite 验证。

SQLite schema 5 增加 `tieban_clause_number`。索引保留 6,847 条已有资料对应的 7,076 个版本编号，其中沐玄 JSON 版 6,192 个，十四表 CSV 版 884 个。编号从源条目选择器导入，同文归并后的原编号均保留。太玄基数以 `muxuan-json` 为条文版本，逐个查询对应编号。项目未收录时返回 `unmatched` 和 `not_in_catalog`，例如算例当天 14 时排盘得到的后天编号 2666。只在另一版本收录，同样记为未命中。时间层、年龄条件和性别限制分别核对。

命中的无年龄本命条文按主题进入报告的铁板起数参考。报告接口另返回各编号的状态，未命中没有对应原文。缺少时柱或性别，以及柱位记录相互矛盾时暂停本次起数。普通子平匹配继续标记铁板条目为 `different_calculation_system`，铁板走独立编号索引。

太玄当前启用两项正卦基数。变卦、元堂、考刻定分和十四表流年继续待接入。资料包的默认分类偏移及人生事实回填继续保留为原包研究材料。

## 皇极两项基数接入

第 36 批依据用户资料包 `references/演算法式.md` 第 3 节和 `scripts/yansuan.py` 的 `huangji_suanfa` 接入两项基数。元、会、运、世分别使用年、月、日、时柱各自的干支太玄数之和。元会依原顺序占两个十进制数位组，运、世各自倒序后再依原顺序占两组。一位数倒序保持该数，数值 10 倒序为 1。例盘庚寅、甲申、丙午、甲午的四项数为 `15、16、16、18`，元会得 `1516`，运世得 `6181`。

皇极和太玄都从已验证的完整本命四柱起数，用已确认性别核对条文资格。两套结果在同一 SQLite 读事务中按各自版本和编号查询。`tieban.results` 保留太玄结果，`tieban.additionalCalculations` 标明皇极的口径、版本与逐号状态。`1516` 在项目沐玄 JSON 版未收录，返回 `unmatched / not_in_catalog`。`6181` 命中 `tbss-v6-clauses-p06181-001`。值为 `909` 或 `101` 的短编号保留原数，按版本查空。流年、年龄或性别门槛分别沿用项目既有条件。

报告仅引用已匹配的本命条文。每个编号标明太玄先天／后天或皇极元会／运世，同一条文重复命中时保留编号说明并只引用一次原文。参见 [原生排盘样例](claims/tieban-huangji-witnesses.json)。考六亲加数、初刻加数及逐岁算法仍待核对，例盘中与考刻有关的 `9516` 和 `10416` 不进入这次起数。

覆盖核对使用原生盘检验 720 组年柱／月柱与 720 组日柱／时柱，并分别核对男、女取条条件。相较太玄两项基数的 25 个可匹配源 ID，皇极新覆盖 48 个本命源 ID，其中元会 21 个、运世 27 个。常规子平索引条数保持原统计，皇极条文经专用索引进入报告。

## 日柱配卦与年月变卦五式接入

第 37 批依资料包 `references/演算法式.md` 第 4 节及 `references/乾集起数规则.md` 第 5、14、17、20、24 节实现。日支定上卦、日干定下卦。上卦取外卦三爻、下卦取内卦三爻，各爻加总纳干与纳支太玄数，等于 10 的整爻弃数。上下卦纳数依次合成编号。支配卦采用资料包该版的卯属乾、申属艮。先核完整本命柱位及性别。

年月变卦以年、月各柱太玄数取先天卦，上下互置后由新上卦定前两位。末两位分别取本卦上卦纳数、本卦下卦纳数、本卦卦数、本卦互卦数、变卦卦数。启用资料包列有算例的五式，资料包列为推断的三式保留待核。以实际卦序与爻序核算，资料包所记的异名继续保留在来源说明。

原生例盘癸巳、甲子、丁酉、甲辰复现日柱编号 `3926` 和年月编号 `8239`、`8226`、`8212`、`8253`、`8221`。全部按沐玄 JSON 版精确查询。`8253` 在当前项目未收录，返回 `not_in_catalog`。`8226` 匹配项目 JSON 版「兄弟三人，我在空门」，演算段与十四表同号异文保留原出处与计岁记录。不同版本各自查号。

覆盖核对逐一复算 720 组年／月柱和 60 种日柱，新增 70 个此前两种起数未覆盖的本命源 ID。其中日柱纳数 9 个，年月五式共 61 个，合计 143 个本命源 ID 可由现有三种起数命中。每条都有项目实际排盘、SQLite 和报告材料验证。接口在 `tieban.additionalCalculations` 保留本方法的逐式编号和状态。见 [原生验证样例](claims/tieban-day-hexagram-witnesses.json)。

## 河洛天地数与元堂接入

第 38 批按资料包 `references/演算法式.md` 第 2 节及《乾集》相关段落。天干取河洛卦数，每个地支同时取生数、成数，奇数相加为天数、偶数相加为地数。超过 25 或 30 时各减对应常数，再取个位，个位为零时取十位。阳男、阴女取天数在上，阴男、阳女取地数在上，两端均用后天卦数。资料包的阴阳合卦和三元取法另见 [《天机道》对应章节](https://vr-d.com/pdf-file/%E7%B4%AB%E5%BE%AE%E6%96%97%E6%95%B0%2F%E5%A4%A9%E6%9C%BA%E9%81%93-%E5%80%AA%E6%B5%B7%E5%8E%A6%E7%AE%80%E4%BD%93-%E5%80%AA%E6%B5%B7%E5%8E%A6.pdf)。

余数 5 时按资料包公历年份区间寄宫。客户端只在出生时间明确的八字报告请求附出生年，后端在余数 5 时核对该年与实际年柱，子、丑月允许交年前仍用上一年干支。缺失或矛盾时该河洛候选不生成。年月仍由引擎在真实交节时刻定柱，出生年份附加字段只用于起数。

后天卦通常上下互置，元堂爻随卦移动三位后再翻转。坎、屯、蹇依第二百八十四批核对的河洛月令特例处理。纯乾女命、纯坤男命按最新中气分冬至至夏至、夏至至冬至。旧资料在午、子月缺少中气，或资料存在矛盾时，只算先天。二阳的寅、卯时和二阴的申、酉时属重数第二轮，资料包注明个别次序仍是复原，保留待核。

原生盘复现 `1497`、`2666` 以及下元寄宫例 `5918`、`8237`，四个例号在项目的沐玄 JSON 版均未收录，返回 `not_in_catalog`。在 27,434 张原生盘中验证了 13 个可由河洛匹配的本命源 ID，这些 ID 已在此前的 143 个覆盖范围内，继续按实际命盘提供河洛编号参考。 [原生验证样例](claims/tieban-heluo-witnesses.json)

## 书传流年推算接入

第 62 批采用资料包 `references/乾集起数规则.md` 第 27 节、`references/演算法式.md` 第 5 节和 `scripts/yansuan.py` 的 `liunian_shuxu`、`shuchuan_liunian`。原诀说流年还看年干支。资料包参照《破解钥匙》将个位改为流年干数加流年支生数，千位继续用月干数加所在大运干数。百位仍取日干，十位仍取时干，遇十按十进制进位。保留大运干数是资料包的复原口径，原书没有流年命例可验。`8651` 是资料包的算术自检结果。
