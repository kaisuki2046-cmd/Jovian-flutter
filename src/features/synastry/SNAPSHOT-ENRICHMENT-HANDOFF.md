# 合盘后续快照字段交接

2026-11-18。当前静态算法使用账户已公开的命盘快照，前端仍录入双方出生信息，并展示四种关系的解读。

## 后续依赖

下列内容需要命理与账户负责人确认契约后实施。

| 功能 | 所需上游字段 | 用途与缺项处理 |
| --- | --- | --- |
| 紫微庙旺及派别格局 | 星曜亮度、所用安星与亮度表版本 | 现有投影只保留星名和四化，合盘据现有字段提供结构事实 |
| Davison 时空中点 | 双方已解析出生 UTC 瞬间、出生地坐标、时间精度、历法与历史时区处理版本 | 当前 calculatedAt 仅是计算发生时间。缺少出生瞬间时保留方法登记，停止 Davison 计算 |
| 八字大运与流年 | 每人的起运法、顺逆参数、起运边界和运柱有效区间 | 先按人计算，再以独立 targetTime 作共同时间轴 |
| 紫微运限 | 每人的大限、流年宫位及各层四化、日期边界和流派版本 | 保留本命层，新增时间层，不覆盖既有宫名 |
| 西占次限、太阳弧与回归 | 可用出生瞬间、对应技术的时间钥、地点策略及星历口径 | 各技术独立实现和验证，不能用计算时间代替出生或目标时间 |

这些都是后台契约字段，当前任务没有要求新增关系或场景输入。共享字段只通过所属模块公开接口提供。

## YA 快照契约接入

公开 `SynastryChartSnapshot` 已支持可选的星曜亮度、表版本与生年四化来源。手填 A/B 和账户投影使用同一字段契约。本人接口显式指定 `calculationContext=1` 时，可从新的精确时刻快照读取出生 UTC、分钟精度、出生地点坐标、时区口径与适用的八字起运上下文。旧档缺失字段时继续使用已有静态事实。不能用 `calculatedAt` 代替出生时间或根据同星标记推定四化来源。

出生计算上下文仅供本机计算。模型请求仍由允许的比较事实和命中资料组成，星曜亮度和四化起源可转为中文事实。接入涉及以下主要文件：

| 文件 | 用途与影响 |
| --- | --- |
| `src/features/account/history/model/synastry-snapshot.ts` | 声明亮度、四化起源、可用出生瞬间及精度等公开可选字段，不改变现有必填字段。 |
| `src/features/account/history/model/synastry-projection.mjs` | 从已授权归档投影经过核对的计算上下文，不补猜旧档案缺项。 |
| `src/features/account/history/model/chart-snapshot.mjs` | 对新增持久化字段执行实际服务端校验，保留旧版兼容。 |
| `src/features/account/server/chart-snapshot.test.mjs` | 验证投影归属、精度、缺项与兼容行为。 |
| `src/features/destiny/model/chart-snapshot.ts` | 在产生新归档时保存可核对的出生计算上下文。 |
| `src/features/destiny/control/charts.ts` | 明确原始星曜亮度和起化来源与版本，不改既有算法结论。 |
| `src/features/destiny/control/manual-subject.ts` | 手动A/B与账户投影使用同一新增契约，保留双方独立归属。 |
| `src/features/destiny/reading.test.mjs` | 验证真实排盘至新增投影字段的一致性、未知时刻与旧结果行为。 |

动态运限、Davison、推运等方法仍需独立定义目标时间、方法参数及来源口径。当前静态流程只消费已实现的星曜和四化事实。逐项缺口见 [条件映射进度](CONDITION-MAPPING-PROGRESS.md)。

## 原交接验收要求

用明确出生时刻和地点的虚构资料验证投影前后精度、版本和归属一致，并测试旧快照缺少新增字段时的行为。动态事实单独携带 targetTime、有效区间及 profile，不能由静态事实猜测。

后续动态方法实施后，将剩余接口说明迁入对应模块文档。
