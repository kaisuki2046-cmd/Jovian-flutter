# 合盘开工说明

协议版本 **v1.2**。开工前阅读[仓库开工说明](../../../AGENTS.md)、[协作协议](../../../COLLABORATION.md)、[框架图](../../../FRAMEWORK.md)和[合盘说明](README.md)。

## 职责与授权

合盘负责两人的出生资料录入、校验、双人盘面比较和结果展示。开工时声明 MVP、验收条件、负责范围、基线提交和预期公共 UI 变更。

- 本模块的写入和提交范围以当轮用户授权为准。认领合盘时，范围为 `src/features/synastry/` 及任务所需的兼容公共 UI 改动。
- 命理、运势、账户和路由分别由所属负责人维护。跨目录改动须事先向用户说明具体文件、用途和影响并取得明确授权。根级文档、脚本、配置、依赖和 CI 同样适用。
- 需要复用单人排盘时，先由命理负责人确认输入、输出和缺失资料的行为，再通过命理的公开入口调用。合盘负责双人比较逻辑。
- 本地 MVP 使用用户手动确认的双人资料。账户资料回填、归档及服务端传输分别确认用途、最少字段和授权。账户侧读写经账户模块公开接口处理。

> **跨板块协作**　其他板块的代码可以阅读和参考，可通过对方明确开放的入口或公共 UI 复用能力。需要修改认领范围外的文件时，包括其他板块的代码、业务页面和说明文档，须先向用户说明具体文件、原因和影响，取得明确授权后再修改。

## 实现与验收

`model/` 定义双人输入和比较结果，`control/` 负责校验和比较，`view/` 负责表单和结果展示，`index.ts` 对外提供页面及明确约定的接口。随实现创建所需目录。

验证完整输入、缺失或不合法的资料、计算失败、修改资料后重算，以及路由接入后的访客和会员访问。测试用例使用虚构资料。

子树默认从最新 `origin/dev` 开任务分支，记录基线提交。现有 `check:scope` 暂未登记 `synastry`，按协作协议人工核对暂存差异和逐提交路径。子树 PR 默认指向 `dev`，由集成负责人按最新 `origin/dev` 复验合并结果。推送和合并按用户授权执行。
