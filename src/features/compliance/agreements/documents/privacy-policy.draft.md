## 二、处理的信息与用途

| 场景 | 涉及信息 | 用途与范围 |
| --- | --- | --- |
| 账号与登录 | 实际使用的邮箱、手机号、第三方登录标识、认证及会话信息 | 注册、登录、账户安全；仅说明正式启用的登录方式 |
| 验证码（按启用渠道） | 邮箱或手机号、对应投递内容、挑战及必要状态 | 用户主动请求的注册、登录或安全校验，不自动用于营销 |
| 可选实名（条件启用） | 本人姓名、身份证号及最小化核验结果 | 主动完善账户资料；传输前单独告知和确认，不作为命理、运势、合盘、算事统一准入门槛 |
| 个人资料 | 昵称、简介及用户选择提供的资料，如通过系统选择器选中的头像、封面 | 编辑和展示个人资料。当前 Android 测试实现把所选头像和封面保存到应用私有目录，正式配置以实测为准 |
| 命理 | 出生日期、出生时间、出生地区、性别及生成的盘面信息 | 排盘、解读和用户要求的记录保存 |
| 运势 | 选定的盘面、周期、显示时区及相关计算事实 | 生成对应周期的内容 |
| 合盘 | 双方获准提供的出生资料或盘面信息 | 计算双方盘面对照并生成解释；尽量不附带身份信息 |
| 算事 | 问题、必要的补充或追问、起卦及抽牌相关结果 | 理解问题、完成计算、生成和恢复对应结果。当前附件由用户通过选择器主动选入，本机对话使用，当前问题理解请求仅发送输入文字 |
| 支持与运行 | 用户主动提交的反馈及必要的错误、运行记录 | 排查问题、保障运行；具体字段和保存期限待确认 |

只处理功能所必要的信息。是否保存出生原始资料、完整盘面、问题、报告和日志，以及各自保存位置与期限，必须在上线前逐项核实并披露。未接入的广告、分析或支付服务不能提前写成正在使用；也不能未经审计承诺“绝不收集任何其他信息”。

登录、投递和实名的字段、供应商及选择说明见[账户登录、验证码与实名告知](account-verification.draft.md)。正式版只保留实际启用场景；本人核验一致不证明已经完成活体识别，也不自动代表所有法定实名要求均已满足。

## 三、本机、服务器和第三方处理

部分计算可在设备执行，部分功能会向应用服务端或第三方 AI 请求处理。正式版应明确区分本机保存、运营者服务器保存和供应商处理的数据。

当前代码存在 DeepSeek 调用，也存在其他模型供应商适配路径；正式版实际启用哪些供应商、哪些接口及其接收字段，须按发布配置核定。第三方 AI 共享的告知及授权见[AI 服务与数据共享告知及授权](ai-data-sharing.draft.md)。不能因数据已转换成盘面或结构化事实，就一概宣称其不再涉及个人信息。

第三方清单需披露：供应商及服务名称、处理目的、数据类别、适用政策链接、保存或删除安排，以及实际涉及的数据处理地区。跨地区传输安排以实际部署和适用要求为准，不能由当前开发环境推定。

拟申请的微信、QQ、邮件推送、短信或短信认证、身份证二要素核验，按[账户告知](account-verification.draft.md)登记各自的接收方、权限、收集时机与字段，区分服务端 API 和原生 SDK。申请中的能力在上线前保持待接入状态。模板、平台授权及验证码的用途限于相应账户操作。接入前应核实原始证件号、验证码或登录令牌仅用于对应账户处理。

若以后启用第三方购买管理、统计、推送、云存储或 AI 推荐，应在启用前核实实际数据处理并更新清单。没有 SDK 不等于没有数据处理，使用 SDK 也不自动满足隐私要求。推荐或画像需说明资料类别、用途和用户可控制的设置，不要求公开源码。

【待确认：第三方最终清单、数据处理条款、保存期限、是否用于训练及相关控制方式。未核实前不作“不训练”“零留存”等承诺。】

## 四、共享、公开与他人资料

资料的公开展示应遵循用户实际选择，不把对其他用户可见与同意交给第三方 AI 处理合并为一个授权。推荐、广告、社交等新增用途如涉及额外处理，应另行说明并取得所需许可。

提供另一人的资料用于合盘前，需要确认适当的处理依据与必要授权。若无法满足相应条件，应提供不上传该人资料或不使用云端解读的路径，而不是以录入者一次勾选代替所有授权。

## 五、保存、删除和安全

正式发布前应确定下列项目的保存期限或确定期限的标准：账户信息、会员报告、访客记录、算事会话、合盘临时数据、授权记录、运行日志和备份。开发代码中的期限不直接作为线上统一承诺。

【待填写：各类数据的保存期限、存储地区、备份删除周期、必须保留项目及依据。】

采取与信息及处理风险相适应的访问控制和安全措施。正式版使用的传输、存储及供应商保护措施须经过实际核验，不在本草案中承诺尚未实现的技术能力。

## 六、用户的选择与权利

用户应能查看和更正适用的个人资料、管理可见性，按功能管理和撤回相关授权，并申请删除数据或注销账号。具体入口和可用方式需与正式版实现一致，参见[账号注销与数据删除说明](account-deletion.draft.md)。

撤回 AI 共享许可后，应停止此后依赖该许可的数据发送；撤回不等于自动删除已经保存的报告或已完成的第三方处理，需要删除的内容应提供相应请求方式。可选授权的拒绝不应导致无关功能被无必要地限制。

## 七、未成年人、权限和更新

面向何种年龄用户、未成年人适用的资料与授权安排，须结合首发地区和实际服务确定；App Store 年龄分级不自动替代相关判断。

按需申请系统权限，并在申请时说明用途。手动填写出生地点不等于获取设备实时定位权限；未实际使用的权限不应申请。

重大政策变更应清楚告知，必要时重新取得许可。隐私政策应在 App 内和公开网页持续可访问。联系方式、权利请求处理方式及时间安排需在上线前填写完整。

Android 拟选商店的隐私申报、SDK 清单及分发包权限应与本政策和真实构建一致。筹备 iOS 时再核对 App Store Connect 及原生隐私清单。安全事件与隐私投诉的接收渠道、责任人及处理安排为【待确认】。
