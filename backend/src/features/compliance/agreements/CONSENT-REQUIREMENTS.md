# 协议版本、确认与撤回要求

状态：内测环境已接入登录页勾选、分身份确认、版本留档及四项 AI 用途的独立授权和撤回。没有配置正式文本时，界面和记录使用标记为内测的版本。

账户服务启动时可通过 `APP_AGREEMENTS_FILE` 指定正式目录 JSON。根键为 `terms`、`privacy`、`ai`，每项包含 `version`、`title`、`sections`，其中 `sections` 的每项含标题 `title` 和正文 `text`。正文已确认后如需变更，发布新版本。服务端根据实际正文生成哈希，用户通过 App 读取并确认同一份版本。

登录页底部提供未预选的协议勾选、现行版本阅读入口。邮箱、手机号、新注册、第三方登录和游客入口均校验明确勾选及当前版本；身份验证成功后才在当前用户下留档。现有会话如缺少当前版本记录，会回登录页确认。模型服务在发送请求前通过账户服务核验该用途授权。读取历史、命盘计算和无需模型的提运建议沿用各自权限。

## 一、分开管理的记录

| 记录 | 建议字段 |
| --- | --- |
| 协议目录 | agreement_id、标题、类型、当前版本、语言、生效时间、是否需要确认、发布状态 |
| 不可变的协议版本 | agreement_id、version、正文、content_hash、发布时间、变更摘要 |
| 用户确认事件 | event_id、受信任的账号或访客标识、agreement_id、version、content_hash、ACCEPT/ACKNOWLEDGE/WITHDRAW、服务端时间、App 版本、语言、入口 |
| 用途授权 | scope、接收方、数据类别、目的、授权状态、关联确认事件 |

后台维护的发布状态至少区分 draft、published、retired；草案不得充当当前有效协议。更换正文必须生成新版本，不能原地覆盖已确认版本。

用户标识和发生时间以服务端校验为准，不接受客户端伪造的同意状态。访客身份通过账户提供的受信任接口取得；访客确认不能无条件迁移为某个会员的确认。

## 二、建议授权用途

初版先记录以下候选用途；是否逐功能确认还是共享明确的等价范围，待用户确认：

- destiny.cloud_interpretation：命理云端解释所需数据。
- fortune.cloud_interpretation：周期运势云端解释所需数据。
- synastry.cloud_interpretation：合盘云端解释所需双方数据。
- divination.cloud_assistance：算事问题理解、必要上下文和 AI 解读。

公开资料、推荐、营销和 AI 共享不是同一用途，不自动相互授权。无实际使用的用途不提前开启。

2026-11-19 登录申请补充：第三方登录及验证码按[账户告知草案](documents/account-verification.draft.md)与真实使用流程披露，不把发送操作性验证码视为营销许可。可选实名候选用途为 `account.real_name_verification`，只在本人主动发起、看清字段/接收方/结果保存安排后记录本次确认；不继承 AI 或登录许可，也不作为四个业务板块的统一门槛。确认记录可引用核验请求标识，不夹带完整证件号、验证码或平台令牌。

平台授权、本站协议确认、社交解绑和本站注销分别处理。撤回社交数据访问及可选后续核验需要实际入口；已完成处理、必要保留和删除请求按真实规则说明。实名当前为表单预览，提交只检查服务可用性。

## 三、确认与撤回流程

1. 首次进入适用流程，显示清楚的告知和完整协议入口；AI 数据发送前取得必要许可。
2. 需要用户选择的项目不默认选中，不把可选授权混入一个强制总勾选。
3. 后台校验版本、正文哈希、适用范围及身份，防重复写入；重试不应产生相互矛盾的记录。
4. 撤回只停止依赖该项许可的后续处理，不顺带关闭无关功能。
5. 撤回和正在发起的数据发送如何协调必须测试；不能在用户撤回后仍以旧状态发起新的请求。
6. 供应商、用途或数据类别实质变化时，评估是否需要重新确认；不能用普通提示冒充重新授权。

记录对用户的展示不包含认证凭据或内部密钥。授权记录本身也需访问控制、保留期限和删除安排。

### Android 首次运行与登录接线

- 在同意前提供能完整阅读的隐私政策和用户协议。首次运行应先呈现告知；涉及该同意的账号、设备资料处理和 SDK 初始化等到用户明确选择后再开始。清空 App 数据后，记录打开、拒绝、接受及重启四条路径的操作和网络证据。
- 登录页使用「我已阅读并同意《用户服务协议》《隐私政策》」。未勾选时可以阅读协议，登录、注册提交及游客体验不可用。协议重大更新先在登录页重新确认，站内通知服务开通后再补更新提醒。
- 启用微信或 QQ 前，在对应登录入口说明用途、接收方和实际处理字段，且能查看第三方清单。用户取消时返回登录页，保留其他实际可用的方法。登录流程的说明和记录不替代后续单独的 AI 用途授权。验收见[Android 首发清单](../reports/ANDROID-RELEASE-CHECKLIST.md)和[登录申请包](../reports/SOCIAL-LOGIN-REVIEW-PACKET.md)。

## 四、与既有数据的关系

不补造历史同意，不推定旧用户已接受新增授权，不修改历史报告正文。新增许可对后续需要该许可的发送生效；历史查看不加入内容补审。收到用户主动删除请求时，另按删除流程处理。

## 五、未来验收

- 未取得必要 AI 共享许可，不发送相关个人数据。
- 拒绝与撤回不会引发无关功能不可用。
- 拒绝、接受、撤回及重新确认能追溯到真实版本和身份。
- 后台管理系统不向普通用户展示；协议、撤回和注销等入口仍然可发现。
- 协议确认记录不与审核规则、内容审计日志放在同一份 JSON 文件。
