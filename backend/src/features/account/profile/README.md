# 基础个人资料

- **职责**：管理当前用户的昵称、头像等基础资料。
- **可能输入**：当前用户身份、资料读取请求或更新内容。
- **预期产出**：授权范围内的个人资料字段或更新结果。

当前资料页可编辑昵称、个人简介及出生资料，分别设置公开或保密，并预览他人可见的资料页。服务端按会话识别当前用户，对外仅返回获准公开且已填写的字段；邮箱与手机号始终保密。头像目前使用默认占位，不包含上传功能。资料和请求属于账户，通用控件共建待办见上级 UI-REQUESTS.md。

> **跨板块协作**　其他板块的代码可以阅读和参考，可通过对方明确开放的入口或公共 UI 复用能力。需要修改认领范围外的文件时，包括其他板块的代码、业务页面和说明文档，须先向用户说明具体文件、原因和影响，取得明确授权后再修改。

## 协作约束 v1.2

本目录归 `src/features/account/profile/` 管理；默认只改认领范围及本任务相关的 `src/ui/`。业务模块之间不能相互改文件，修改其他目录前 Codex 必须先向用户询问具体范围和影响，获得明确授权后再做。独立认领更小子目录时按更小范围执行。

业务目标采用 `model/`（数据）、`view/`（具体 UI）、`control/`（功能），现有文件按后续任务渐进整理，不表示已迁移。业务请求仍留在本模块 requests；公共 UI 只接收数据、状态和回调。

按 MVP 验收逐步迭代。公共 UI 的破坏性接口或全局风格变更先向用户确认；提交只包含本轮范围，保留并行改动，结束时列出实际目录、共享组件影响和验证。详细规则见 [本目录开工说明](AGENTS.md)、[协作协议](../../../../COLLABORATION.md) 与 [框架图](../../../../FRAMEWORK.md)。
