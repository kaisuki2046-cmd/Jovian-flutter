# 运势

- **职责**：定义运势周期、输入规则和解读格式，按需通过账户公开接口读取获准使用的时区。
- **可能输入**：查询日期、运势周期和时区。
- **预期产出**：指定周期的运势解读，以及可交由账户模块归档的内容。

## 页面入口

从[命理首页](../destiny/README.md)的「周期运势」进入，`/fortune` 和旧模块跳转继续可用。运势页面、周期规则和公开入口 `FortuneScreen` 由本模块维护，路由注册由[应用入口](../../app/README.md)维护。

## 独立提运建议

「今日」在命盘可用时显示提运建议，使用可确认的本命日干五行、太阳星座或命宫首颗主星匹配资料。已有日运报告时复用该报告的计算记录，也可直接按盘面获取建议。

SQLite 返回按数字、饰品、颜色分组的候选，可在「查看建议依据」中查看出处及局限。建议仅供日常象征搭配。

`GET /fortune/advice/:calculationRunId?expectedOwnerId=...` 使用已核对的账户和命盘，返回按盘面匹配的建议。独立 `advice-` 缓存随建议规则及资料变化刷新。服务端也提供 `GET /fortune/advice/options` 和 `GET /fortune/advice/options/:optionId` 供资料主题查询。

## 资料源与 SQLite 运行库

资料、匹配规则和建议分组都在 [fortune_knowledge.json](model/knowledge/fortune_knowledge.json) 中维护。各周期根据自身计算结果查询同周期已接入的规则，命中资料不足时显示简短提示。带项目时长或宫制假设、缺少可核原文条件的西方行运条目作为待核验资料保留。各周期的完整、部分和待接入数量以 `audit.mjs --summary` 为准。文件以两空格缩进，每条资料使用全库唯一的整数 `id`。建议主题通过 `entryIds` 引用资料。业务解读和提运建议由服务端查询生成的只读 SQLite。

运势服务启动解读模块时自动核对资料与规则源的 SHA-256，首次或源文件改变后生成 `storage/knowledge/.local/fortune-<hash>.sqlite`，随后以只读连接查询。构建先校验资料、ID、规则引用与数据库完整性，再发布完整文件；构建失败不会覆盖旧库，也不会回退到直接读 JSON。新库在服务重启后生效。`.local/` 是已有 Git 忽略目录，不提交数据库二进制；其他机器拉取源码后会自动重建。使用项目现有 Node.js 22.13+ 的 `node:sqlite`，无需新增 npm 依赖。

可手动构建并查看条数：

```powershell
node src/features/fortune/storage/knowledge/manage.mjs
```

SQLite 按术数、资料类别、报告栏目和唯一编号保存资料及匹配规则。迁移条目的 `legacyId` 保留旧引用，`legacy` 保留原有审阅和出处细节。服务端从 `server/knowledge/runtime.mjs` 安装 SQLite 读取器。字段约定及新增资料步骤见 [资料维护说明](KNOWLEDGE_PIPELINE.md#单文件资料结构)。

运行匹配时，SQLite 按当前周期、术数、事实类型和层级查询候选条件，对必需条件和排除条件分别汇总命中与未知。运势控制层再求命中事实的有效时间交集并扣除排除时段，保留逐条匹配状态。首次启动新版服务会生成带条件索引的新库文件。

解读的完整映射、独立确认路径和待复核条目可用覆盖审计查询。历史阶段记录见 [条件映射进度](CONDITION_MAPPING_PROGRESS.md)。228 条独立建议均可按来源和主题匹配，其中 38 条也能按盘面匹配。

学堂另有 [分取法与同段大运计算](BAZI_SCHOOL.md)，记录四生宫、年命纳音、日干月时对照及逐柱刑冲破空；不把引擎表或交运周岁当成完整来源结论。

小运另有 [分方法与同段岁运计算](BAZI_MINOR_LUCK.md)，不把引擎小运、立春年序或单颗禄马直接认作完整来源条件。

Lilly 回归资料另有 [同年成对事实与来源尊贵表](LILLY_RETURNS.md)，区分本质位置、综合状态与同度口径，并保留影印/转录差异。

Lilly 的 [分项偶然条件与正文复核](LILLY_CONDITIONS.md)继续区分结构和综合状态，保留两列orb及定义/示例差异，不按数量打分。

## 模型输入的自然语言转换

四条《全书》太阳、武曲、破军资料补[同段诗诀条件](ZIWEI_VERSE_LIMITS.md)：不同卷的等级和具名太阳阶段分别表达，星位不代救应；太阳撤回未经确认的二限同守门槛，武曲补回入庙并接受实际小限。仍缺来源语义时保持部分，不发成命中原文。

六条《全书》资料已补[身命与同段岁限](ZIWEI_BODY_LIMITS.md)，独立核身宫，并分别保留三层位置、源生年四化及年度延用候选。身宫不由命宫代替，二限不同宫也不被未核原义提前排除；刑忌指代及实际救应继续留缺项。

三条《三命通会》资料已补[岁干与本命同柱关系、制合见证](BAZI_ANNUAL_RELATIONS.md)：日时干岁合不能由年月干代替，干支俱合不能跨柱拼；甲戊制合的透藏、整柱和实际运段分开核，未见与未知保持区别。三条仍有作用条件待核。

36 条 Leo 推运上升资料共用本命优先、十分度和同期方向的事实。第二、第三十分度与整座背景合读。24 条已完成独立倾向的条件，另 12 条的原文前提仍待核。 [推运上升与十分度](LEO_ASCENDANT.md)

`control/fortune-prompt.mjs` 将查询周期、范围及命中资料组装成 DeepSeek 的中文用户消息。事实计算、资料匹配、事件时间线和证据引用均在服务端处理。需要检查盘面细节时可查看本地审计。

每条命中资料提供 **命中条件、原文、现代释义**，同源资料附分组。原文和释义分别来自资料的 `originalText` 和 `modernInterpretation`。缺少完整命中资料的栏目按依据不足处理。

模型响应为三栏 JSON，每栏只含 `sectionId` 和 `summary`。服务端依据各栏的命中资料关联证据并保存审计记录。Prompt 版本纳入解读策略哈希，新生成的报告使用当前版本。

## 周期解读

进入后优先回读当前账户当前规则下最近保存的运势。从指定命盘进入时，按该盘、周期、时区和周期起点查找存档。切换今日、本周、本月和本年时先读已有结果，缺少本期有效报告时使用「解读」。年度解读填写太阳回归地点后，也从同一个「解读」按钮提交。同一周期内刷新时钟或重进页面不自动请求模型。周窗口从周一起算，展示范围按设备时区计算。周运目前只计算西方占星并查询对应周运规则。

生成结果通过账户公开的 `reading-history` 接口自动归档，可从「查看已存解读」回看历史及分页读取。页面标明报告对应的日期范围，旧周期的报告不会冒充今日结果。归档失败保留已生成正文并提供「重试存档」，重试只保存正文，不重新解读。页面通过 `/fortune/reports/latest` 自动回读与当前规则、盘面和周期都一致的报告，必要时补存到账户。此接口校验账户盘面权限，不调用模型。

命理档案通过账户公开接口读取，解读输入为 `report.chartSnapshot`。会话切换后重新初始化页面。缺少档案或快照时，页面引导用户在命理页完成测算。

命理归档已提供本命盘快照。现有字段及后续个性化计算所需数据见[接入审查](FORTUNE_CURRENT_STATE_AUDIT.md)。

每个周期统一展示「综合运势」「财运」「桃花运」。三栏正文由 DeepSeek 根据命中的资料库要点和可确认的个人线索撰写，依据不足时由模型在对应栏目说明。

### 周期事实与回放

四周期事实可通过公开的 `buildFactTimeContext`、`calculateFortuneFacts` 和 `validateFortuneFacts` 使用。八字、紫微、西方分别直接扫描目标窗口，通用黄历用独立方法标识。生成解读或按盘面获取建议需要新计算记录时，Web 端以 `/fortune/time` 的 UTC 时间为参考，在本机使用已经获准读到的本命快照排盘。请求发送标准化事实、方法状态、参考时刻、周期窗口和本命建议主题。完整本命快照和原始计算依据正文留在客户端预览链路。

运势服务设置 `FORTUNE_ACCOUNT_BASE_URL` 与 `FORTUNE_FACT_DIRECTORY` 后，可使用下列接口。目录设为服务专用的私有数据目录。请求保留既有账户会话的 Cookie 或 Bearer，归档 ID 用账户返回的记录 ID。服务核对账户归属、事实版本、周期窗口、记录格式和来源编号，再把事实绑定到服务端计算记录。正式解读和提运建议使用已收到的事实及主题查询服务端资料库。

| 接口 | 输入与输出 |
| --- | --- |
| `POST /fortune/calculate` | JSON 含 `expectedOwnerId`、`snapshotId`、`periodType`、`displayTimezone`、`factBatch`。可选 `weekStartsOn`、`targetPeriod`。批次含 `version`、`asOfUtc`、`window`、`methods`、`facts`、`adviceThemes`。核验并保存后返回报告 ID 和方法状态。 |
| `GET /fortune/reports/:reportId/facts?expectedOwnerId=...` | 核验会话后返回标准化事实、原始依据编号、时间和版本。旧的服务端计算记录继续提供已存的原始依据正文。 |
| `POST /fortune/reports/:reportId/replay?expectedOwnerId=...` | 对客户端提交的记录校验已存事实的哈希。旧的服务端计算记录沿用原时钟和原归档重算。校验不一致返回 409，历史记录仍可读取。 |

对照表、运行口径及跨模块缺项见[事实层现状审查](FORTUNE_CALCULATION_CURRENT_STATE_AUDIT.md)。

### 解读规则与历史报告

Web 通过运势服务获取三栏正文。生成流程统一使用当前资料库匹配结果。诊断接口 `GET /fortune/rules/status` 提供规则数量和版本。

| 接口 | 输入与输出 |
| --- | --- |
| `POST /fortune/interpret` | JSON 含 `calculationRunId`、`expectedOwnerId`，可选 `preferences`、`language: "zh-CN"`。从授权的计算快照生成并保存解读报告。 |
| `GET /fortune/interpretations/:interpretationRunId?expectedOwnerId=...` | 读取对应解读快照。 |
| `GET /fortune/reports/:reportId?expectedOwnerId=...` | 读取已保存的 API 正文报告。 |

已有解读可从历史存档按报告 ID 读取。

运势服务通过 `FORTUNE_DEEPSEEK_API_KEY_FILE` 读取外部密钥文件，也兼容现有的 `DEEPSEEK_API_KEY_FILE`。默认模型为 `deepseek-flash`，可用 `FORTUNE_DEEPSEEK_MODEL` 指定模型。启动已配置账户 URL 和数据目录的本机运势服务时，可在同一 PowerShell 会话中执行以下命令。

```powershell
$env:FORTUNE_DEEPSEEK_API_KEY_FILE = 'E:/deepseek/deepseek api.txt'
node src/features/fortune/server/index.mjs
```

服务用已验证的八字、紫微和西方占星事实匹配资料库，DeepSeek 根据命中的条件、原文和现代释义撰写三栏正文，并说明依据不足的栏目。服务端校验栏目和正文后，关联本地匹配证据并保存报告。请求失败或格式校验不通过时，页面提示重试。

资料库正文或匹配规则变化都会改变服务端解读策略哈希，避免沿用旧版命中结果。持久化解读记录另有 `knowledgeMatches.byMethod`，可逐方法核对每条资料的命中状态。公开正文接口仅返回模型生成的三栏内容。

### 服务端时间

运行 `node src/features/fortune/server/index.mjs` 启动独立时间服务。在启动 Expo 的 PowerShell 中设置 `$env:EXPO_PUBLIC_FORTUNE_TIME_BASE_URL = 'http://localhost:8791'`。服务默认只监听本机 8791，Web 来源默认为 `http://localhost:8081`。使用其他 Web 端口时，在启动时间服务前用 `APP_WEB_ORIGIN` 指定页面来源，可用 `FORTUNE_TIME_PORT` 更换服务端口。

配置服务地址后，打开周期运势或点「刷新日期」时读取 `GET /fortune/time`。如果未配置服务或请求失败，使用设备时间。周期窗口按设备时区展示。
