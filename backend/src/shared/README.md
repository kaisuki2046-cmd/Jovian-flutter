# 共享约定

- **职责**：维护确实由多个模块共用的类型和契约，业务专用规则与类型留在所属模块。
- **可能输入**：多个模块已明确的协作需求。
- **预期产出**：各模块可共同引用的类型定义或公开契约。

## 报告内容与传输上限

[`content-limits.mjs`](content-limits.mjs) 统一内容接收上限：整篇正文 100,000 字符，分段正文 20,000 字符，依据及盘面详情 10,000 字符，算事问题 8,000 字符，报告类 JSON 请求体 16 MiB。字符按 JavaScript 字符串长度计，传输大小按 UTF-8 字节计。上限用于接收完整结果，不是要求模型把正文写满；格式、引用和账户归属仍分别校验，超过上限明确拒绝，不截断后保存。

## 公共请求层

[`http/client.ts`](http/client.ts) 提供统一 HTTP 客户端，处理 API 基址、查询参数、JSON 请求体、空响应、超时、主动取消和错误分类。需要认证的请求显式设置 `authenticated: true`，客户端按需从注入的函数读取 Bearer 令牌。

各功能在自己的 `requests/` 定义接口路径、请求参数和响应校验。模块可为 JSON 响应提供 `parse` 校验函数，为空响应指定 `response: 'empty'`。失败时可用 `RequestError.kind` 区分错误，并在 HTTP 错误中读取状态码和服务端返回的请求编号。

> **跨板块协作**　其他板块的代码可以阅读和参考，可通过对方明确开放的入口或公共 UI 复用能力。需要修改认领范围外的文件时，包括其他板块的代码、业务页面和说明文档，须先向用户说明具体文件、原因和影响，取得明确授权后再修改。

## 协作约束 v1.2

本目录归 `src/shared/` 管理；默认只改认领范围及本任务相关的 `src/ui/`。业务模块之间不能相互改文件，修改其他目录前 Codex 必须先向用户询问具体范围和影响，获得明确授权后再做。独立认领更小子目录时按更小范围执行。

features 按 model（数据）、view（具体 UI）、control（功能）逐步组织；本基础目录保持自身职责，不强行套用 MVC。业务请求留在各功能模块，公共 UI 不承载业务逻辑。

按 MVP 验收逐步迭代。公共 UI 的破坏性接口或全局风格变更先向用户确认；提交只包含本轮范围，保留并行改动，结束时列出实际目录、共享组件影响和验证。详细规则见 [本目录开工说明](AGENTS.md)、[协作协议](../../COLLABORATION.md) 与 [框架图](../../FRAMEWORK.md)。
