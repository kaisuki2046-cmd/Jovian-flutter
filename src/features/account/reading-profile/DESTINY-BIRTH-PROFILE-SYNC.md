# 命理出生资料同步接入

## 账户接口

个人中心和命理使用账户服务中的同一份会员出生资料。命理从账户公开入口导入以下接口。 [账户公开入口](../index.ts)

```ts
const fields = ['birthDate', 'birthTime', 'birthPlace', 'gender'] as const;
const baseline = await requestAccountBirthProfile(memberId, fields, signal);
const saved = await confirmAccountBirthProfile(memberId, baseline, confirmedProfile, signal);
```

`baseline` 是本次编辑开始前读到的账户资料，`confirmedProfile` 是弹窗中展示并经用户确认的四项值。保存成功返回账户实际保存的数据，继续编辑时用返回值作为新的基线。个人中心的出生资料页重新获得焦点时读取最新资料，已有未保存修改时保留草稿。

| 字段 | 约定 |
| --- | --- |
| `birthDate` | `YYYY-MM-DD`，未填写为 `''` |
| `birthTime` | `HH:mm`、只知道小时的 `HH:??`、只知道分钟的 `??:mm`，或完全未知的 `''`。调用 `birthTimeFromParts` 时将未知部分传为 `null`。 |
| `birthPlace` | 命理保存所选地点的完整 `place.name`。个人中心已有资料可为省市区文字或手填文字。 |
| `gender` | `female`、`male`、`other` 或 `''`。按命理现有表单支持的值执行测算校验。 |

保存沿用当前的逐项可见性。首次建档时四项默认保密。同一份资料重试保存可成功。账户已有不同的新值时接口返回 `409`，应保留本次草稿、重新读取账户资料、展示差异并让用户再次确认。身份变化或离开页面时取消请求并丢弃旧会话的返回值。访客沿用本次测算流程。

## 命理页面接入

1. 在 `useDestiny.ts` 中，会员进入或重新聚焦命理页时读取四项账户资料。账户资料作为共享来源，旧 SecureStore 档案可作为待确认的候选。账户资料发生变化时更新下一次提示，保留正在编辑的草稿。同一轮停留中只提示一次。
2. 有已填资料时弹出「使用已保存的出生资料？」。逐行展示**出生日期、出生时间、出生地点、性别**，缺项标注「未填写」，部分时刻展示已知部分和未知部分。资料完整且通过命理校验时显示「使用这份资料测算」，同时提供「修改资料」及关闭操作。地点用完整名称或可唯一匹配的省市区路径在 `birth-places.ts` 中解析。地点重名、未收录、必填项缺失或性别超出表单支持范围时，带着可识别的值进入编辑，让用户核对或补齐后开始测算。
3. 在 `useBirthForm.ts` 和 `DestinyFlow.tsx` 中，填写通过校验后展示相同的四项详情供核对。会员主按钮为「确认并同步测算」，点击后调用 `confirmAccountBirthProfile`，保存成功再开始测算。访客主按钮为「确认测算」。返回修改或关闭弹窗时继续保留草稿。提示同步会沿用个人中心已设置的可见性。
4. 保存期间禁用主按钮并显示进度。网络或校验失败时保留确认内容并允许重试。遇到 `409` 时显示读取到的两份资料并让用户再次选择。成功后刷新命理侧的账户资料和保存基线。用户选择直接使用已保存的账户资料时，可以用本次确认的资料直接测算。历史报告继续使用当次测算的快照。

## 端到端验收

- 会员在命理确认后，进入个人中心能看到四项资料，原有可见性设置继续生效。
- 在个人中心改动后返回命理，提示中展示最新详情。已保存资料可一键确认测算，也可先调整。
- 取消确认后账户资料未变更。旧表单遇到另一端的新保存时得到冲突提示。访客仍可确认测算。
- 完整时刻、只知道时或分、完全未知的时刻均可在两端读回。遇到无法匹配的地点时，编辑页保留原始地点提示并要求用户重新选择。
