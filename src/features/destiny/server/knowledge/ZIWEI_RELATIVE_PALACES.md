## 已接入的文字结构

- “身宫或命宫逢／见某星”保留择一；女命、生年及指定命支等额外条件分别核对，不因星曜出现就忽略宫位。
- “见紫微同宫或对宫”绑定前文的同一主星及宫位；本批破军一条仍要求丙或戊生年和四墓命支，不将别宫紫微拼入。
- “文昌、文曲构成命宫之夹”和“日月位在财帛前后相夹”分别核对两颗星在指定中心宫的前后两侧，两星不能放在同一侧，也不把三合当成相邻夹宫。
- 本批的“太阴与文曲合于夫妻宫”按带明确所在宫位的同处结构处理，不把不带位置的“合照／会照／相合”通用改成同宫。《全书》另条保留“太阴同文曲于妻宫”的表述，来源见原库 `ziwei-v3-c020-p117003`；该条附加的文昌分支没有随同忽略。
- “亥地夫妻宫”可作为明确宫支条件，并能约束同条其他同守条件。真实记录中的“空劫”定名及“坐病地”等尚未解决，原记录继续待接入，没有因前半句可识别而放行整条。

具体6条新增整条：女命廉贞身／命、四墓破军见紫微、日月夹财、捷览明确择一的财印夹命或日月夹财、捷览太阴文曲夫妻宫，以及昌曲夹命。升级整条的两条为《全书》太阴文曲夫妻宫句、天同身／命星性句。两条的条件与原文仍按各自来源保留，不把相似出处合成一条。

## 当前排盘体系的有限校验

编译配置 `iztro-2.6.5-relative-palaces-v1` 只检验当前默认本命算法的可行性。实现见 [布局校验](ziwei-relative-profile.mjs)，对应本机依赖的 [主星安置](../../../../../node_modules/iztro/lib/star/majorStar.js)、[紫府起点](../../../../../node_modules/iztro/lib/star/location.js) 和 [命身宫公式](../../../../../node_modules/iztro/lib/astro/palace.js)。算法版本或默认规则变化时须先复核，不继续套用旧配置。

十四主星由紫微、天府两组固定偏移决定，紫微有12个可能地支位置；每组再遍历12个命支，覆盖144种主星与宫位配置。身宫与命宫的位置差为出生时支的两倍，因此当前默认盘只会落在命、夫妻、财帛、迁移、官禄、福德六类宫位。本批用原生排盘逐一覆盖12种主星布局，并核对六类身宫位置，才使用该有限校验。

有限校验只排除当前算法不可能的组合，不提供个人正面命中，不取代实际出生资料排盘，也不宣称其他历史流派错误。运行时仍由实际盘面事实匹配 SQLite 规则，未知出生时间不保留本批所需的宫位证明。

天同身／命原分句曾展开12个身宫位置，其中6个在默认盘不可能。本批升级整条时保留可实现条件，另记录并移除这6个源内展开枝；不是删除6条资料，也没有改变其他来源的条件。破军同宫／对宫产生的8个不相容交叉组合保存在同一SQLite条目的 `incompatibleAlternatives`，未冒充真实出生证据。

## 来源差异与保留项

《捷览》`ziwei-v3-jielan-122-p001-001` 的提供库明确把财印夹命和日月夹财列为择一、共用同一结果。本批按该固定来源、原文和完整条件签名展开；原文或条件变化就停止此专用展开。没有全局把逗号或“及”视为OR。

《星诀》`ziwei-v1-xingjue-032-p149-001` 的提供库要求两夹局同时成立。在完整144种现行配置中不能同时满足，故继续保留原“且”与原文，列为当前排盘体系不相容、待复核；未将其改成上述《捷览》的择一。这里证明的是与当前默认算法不相容，并未证明原书“及”的唯一文义。

《观测录》紫府夹迁移原句的使用限制明确说明它属于同梁守申命的原例。本批保留为命例，原例星位未一起复核前不作通用本命断语。其他未定义吉煞、空曜定名、病地、原例背景与修饰句仍列在待办中。报告材料保留原资料限制，并增加同宫、对宫和夹宫不可跨宫拼接的计算说明。

## 第三十四批：单坐身宫与值身命

《全书》和《捷览》的铃星条文分别按各自 ID 查询。命宫有铃星即可满足命宫备选，身宫备选须核对实际身宫及同宫铃星。有效身宫宫职为命、夫妻、财帛、迁移、官禄、福德。

《星诀》的「地空单坐身宫」所需证据包括地空在本命身宫、该宫星表完整、核心星组只有地空一颗。当前默认排盘按月位减、加时支定位命宫和身宫，按亥位减、加时支定位地空和地劫。身命重合要求两倍时支索引为十二的倍数，因此地空和地劫也必同宫，无法满足核心星组唯一的条件。该备选及理由保留在审计中。其余五类身宫均有原生盘样例，出生时间或星组证据缺失时对应条文留为未命中。

两部铃星条文各有七组可达条件，《星诀》地空条文有五组。十二份原生盘样例覆盖全部十九组。见 [编译清单](claims/integration-batch-34-20261119.json) 和 [验证样例](claims/integration-batch-34-witnesses.json)。
