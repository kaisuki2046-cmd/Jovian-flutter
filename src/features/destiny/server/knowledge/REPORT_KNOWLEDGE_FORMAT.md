# 命理统一资料库 JSON

[统一资料库](claims/report-knowledge.json) 是一个数组，收录紫微斗数、八字和占星。单条结构由 [JSON Schema](claims/report-knowledge.schema.json) 定义。[数字编号映射](claims/report-knowledge-ids.json) 用于从既有资料版本追溯条目。

| 字段 | 内容 |
| --- | --- |
| `id` | 全库唯一的正整数。沿用已分配编号，新增条目从最大已用编号之后分配。停用可保留编号映射，删除后留下编号空缺。 |
| `source` | `book` 为书名，`locator` 定位到卷章、页码、原段或数据行。可核实的在线出处放在 `url`。仅有归档原件时，`locator` 保留资料的相对位置，`url` 为 `null`。 |
| `category` | `method` 取 `ziwei`（紫微斗数）、`bazi`（八字）或 `western`（占星）。`topic` 沿用综合、事业、爱情、学业和财富。条目描述性格时取 `contentType: "personality"`，描述事件、处境或结果时取 `contentType: "fact"`。查表和计算参考也归为 `fact`。 |
| `originalText` | 原书可引用的判断或原始资料。只有匹配前提或缺少可核实判断引文时为 `null`。 |
| `matchConditions.status` | 必填布尔值。`true` 表示现有程序已接入该条的规则、历史对照或铁板编号匹配入口。`false` 表示条目只有查表用途、尚无匹配规则或已停用。 |
| `matchConditions.original` | 按来源保留能核实的条件原句、标题或表格值。无独立条件原文时为空数组。 |
| `matchConditions.formatted` | 现有匹配层确认的规则、选择器或计算参考。 |
| `modernInterpretation` | 已有现代释义。只有本地匹配前提的条目填 `null`。旧规则没有逐字引文时可保留项目撰写的释义。 |

## 匹配条件

`formatted.kind` 区分个人盘面规则（`chart`）、历史命例（`historicalCase`）、古籍格言对照（`historicalReference`）、铁板编号（`tiebanSelector`）、查表资料（`calculationReference`）、待匹配（`unmapped`）和已跳过（`skipped`）。

`status` 可通过当前 SQLite 的规则、旧规则和铁板编号索引逐条复核。一个分句至少有一条可执行规则即可标为 `true`。历史命例受专用盘面条件约束，古籍格言需显式启用对照。铁板条文须能用现有出生资料按对应版本取号，并通过性别和来源校验。查表资料继续供本地计算和查证，`status` 标为 `false`。

盘面规则的 `alternatives` 是备选规则组。匹配前将共同的 `commonRequired` 并入每组的 `input.required`。组内的 `anyOf` 至少满足一组，`mustBeAbsent` 须确认缺席，`relations` 和 `thresholds` 须同时满足。省略的条件列表按空数组处理。计算口径、检查阶段及运限锚点随适用规则保存。零起始的 `sourceConditionIndexes` 指向同条记录的条件引文，省略时沿用该条全部条件引文。资料库保存全部规则组，本地盘面证据展示实际命中的事实。

同一原段有独立判断时按命中分句整理。不同规则组共用同一个判断和释义时，可归在同一记录下。大运条目从本命盘确认运限的事实时，`chartScope` 记录实际检查阶段，`sourceChartScope` 保留资料声明的大运范围。历史命例、术数计算表、铁板选择器和没有机器匹配的来源各自保留适用范围。铁板编号继续区分版本、年龄和性别口径，来源列出的别名保留供查证。

## 维护及运行

新增或者校订前先核对同版本原文与适用规则。公开链接优先使用卷章、印刷页对应的 PDF 影像页或版本固定的数据行。编录中的解释和归一化条件分别放入现代释义或机器规则。

应用构建 SQLite 时从统一 JSON 读取已启用的盘面规则、历史对照规则和铁板编号选择器，并导入数字 ID 映射。命名的计算口径、排盘和复核逻辑沿用现有实现。三套原始 Claim JSON、校订数据和旧种子保留来源档案、已审阅分句及查表所需的计算元数据。报告请求通过 SQLite 查询。

报告按命中的数字 ID 取原文和现代解读，并附上该条实际通过的匹配条件。合并在同一条目下的备选组仍分别复核原有分句，发给模型时分组列出。完整规则组一致时，保留原先已审阅的分句或已核的大运摘录。没有原文的条目可以使用已有现代解读，仅含匹配前提的条目留在本地查询。查表、待匹配和停用记录按各自类型保留。

现代解读使用自然的简体中文，解释对应分句和古代语境。相关含义明确时，可以给出当代生活中的近似情境。原句只列条件时，释义限于该项条件的含义。现代解读与原句重复时，发给模型的材料保留一次原句，有独立说明时保留说明内容。

验收应验证 JSON Schema、数字 ID 唯一性、各源记录及分句的覆盖，以及接入状态和机器规则组与原 SQLite 输入逐项一致。更新出处和原文条件时，保存能回查的原文位置。若后续拆分条目，应登记新增数字 ID 与原段的关系。

## 铁板资料精简

## 本地待接入资料

随代码提交的统一 JSON 共 14,660 条，每条均已接入匹配。待接入及停用条文共 4,185 条，原文、释义和编号由本机的 `.local/knowledge-review/` 保存。另有 398 条查表记录的解读及数字映射也留在本机，对应的运行计算源继续随代码提供。清理后的项目可直接从随代码提供的资料重建 SQLite。
