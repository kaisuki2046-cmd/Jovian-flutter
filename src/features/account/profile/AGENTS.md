# 账户基础资料开工说明

协议版本 **v1.2**。完整仓库先阅读上级 AGENTS.md、[协作协议](../../../../COLLABORATION.md) 和 [框架图](../../../../FRAMEWORK.md)。只持有本目录副本时，按本文执行并说明缺少上级文件；不要虚构检查结果。

## 本目录的职责与范围

本目录属于账户板块内部。以本目录为独立工作区时，默认任务范围为 src/features/account/profile/。若用户已明确授权账户整体任务，可在已确认的账户范围内联动；子目录文件的职责仍按各自说明执行。

昵称、简介、资料编辑、公开或保密设置及他人视角资料展示。

基础资料请求位于本目录 requests/。预览按服务端允许的字段呈现。保存失败保留草稿，公开与保密的变更纳入未保存状态。与 reading-profile、server、storage 的联动按已确认范围接线。

> **跨板块协作**　其他板块的代码可以阅读和参考，可通过对方明确开放的入口或公共 UI 复用能力。需要修改认领范围外的文件时，包括其他板块的代码、业务页面和说明文档，须先向用户说明具体文件、原因和影响，取得明确授权后再修改。

## 必须遵守的目录边界

默认写入和提交范围为 `src/features/account/profile/`，加上本任务确有需要的 `src/ui/` 样式和通用组件。用户独立认领更小子目录时按更小范围执行。

业务模块之间不能相互修改文件。除认领目录和本轮相关公共 UI 外，修改、创建、移动、删除或格式化任何其他目录前，Codex 必须先向用户询问原因、具体文件和影响，得到明确授权后再执行；已获本轮授权无需重复询问。其他负责人意见不替代用户授权。只读参考不扩大写入范围。

规则同样适用于 src/app、src/bootstrap、src/shared、根文档、配置、依赖、锁文件、脚本和 CI。单独认领账户子目录时，其余账户子目录也是范围之外。公共 UI 是明确的共享例外，shared 不是。

## MVP 与模块 MVC

先声明本轮目标、最小可用流程、验收条件、阶段、允许目录和公共 UI 预期改动，再开始实现。先做 MVP，后续按反馈迭代；不要提前实现未要求的功能或复杂抽象。缺少接口时标记本地替代、占位或依赖，演示成功不代表真实功能完成。

各 features 模块目标采用 `model/`（数据类型、结构、状态、访问接口）、`view/`（业务页面、布局与专用组件）、`control/`（功能流程、校验、计算、状态协调、权限与跳转意图）。目录名统一为 control。view 通过数据和回调连接 control，不直接发业务请求或访问存储。control 调用 model 和本模块 `requests/`，后者复用 shared/http。

采用简单函数/hooks 即可。账户保留功能子目录，按需在各子功能内应用 MVC；server 保留 HTTP 适配，storage 保留持久化，两者无需机械补齐 view。公共 UI、路由、装配和 shared 保持各自基础职责，不强制套 MVC。

这是渐进整理规范，现有 screen.tsx、model.ts、requests/ 等路径尚未全部迁移。新增或触及功能时在本轮范围内分层，保持 index.ts 等公开入口兼容，不整仓搬迁，不复制两份实现。需要改外部调用方时先向用户询问。

## 共同维护公共 UI

src/ui 管理统一 style、主题与可复用组件，所有负责人都能为本轮任务贡献，无需等待专属 UI 负责人审批。先复用已有组件或添加兼容选项；缺失时按现有风格新增，或从自己负责目录抽取通用部分到 ui。未经授权不能搬动别人的业务组件。

公共组件只接收显示数据、状态与回调；业务请求、权限、计算和跳转目标留在业务 control，页面布局与业务容器留在 view。既有公共导航适配保持兼容。复用现有 theme.ts 等样式来源，不擅自改整套风格。

改共享文件前检查并行改动及调用方，保留侧边聊天的调整。破坏组件接口、全局改变默认外观或无法判断重叠修改时先向用户确认。涉及其他业务文件仍须用户授权。

交付说明组件名称、导入路径、使用示例、支持状态、受影响调用方、验证与合入版本。UI 申请为可选记录；暂时不能完成时记录临时代码、缺口和验收条件，完成后说明替换位置与清理结果。不要把未提交或未合入代码称为团队已可用。

## 数据与公开接口

业务请求、后端和数据库实现留在数据所属模块，跨业务只使用提供方 index.ts 明确开放的契约或 bootstrap 注入的接口，不导入内部文件。账户管理用户归属、资料权限与历史归档；其他模块按用途读取获准字段，将允许归档的结果交给账户。推荐用途另行授权，社交遵循账户公开资料范围。接口未交付时记录依赖，不绕过权限。

## Git、验证与结束报告

开工记录分支、起始提交、工作区及暂存区，保留已有改动。账户任务默认在集成负责人指定的持久主工作树开发，同树聊天直接交接本地文件。需要隔离任务时，按协作协议确认任务分支和基线。

只暂存本轮认领目录和相关 src/ui 文件，其他目录必须有用户明确授权；不得夹带他人改动。禁止 git add .、git add -A 和 git commit -a，显式选文件并核对完整 git diff --cached。共享文件含他人改动时按内容区分，无法分离则询问用户。

现有 check:scope 仍只检查单目录。单目录提交可用 --module <板块> --staged；混合业务/UI 提交按协作协议人工核对完整暂存区及每个待推送提交的路径，报告检查方式，不能声称旧脚本支持两个目录。推送和合并按用户授权执行，本地账户改动按授权提交和备份。

模块 *.test.mjs 放回所属目录，公共 UI 测试放 ui。按变化运行 typecheck、check:boundaries 和相关测试；纯文档核对规则、链接和范围。测试使用隔离数据。只有目录副本时交付明确文件清单与验证限制，不覆盖整仓。

每轮结束列出 MVP 结果、后续项、实际修改的业务目录和公共 UI 文件、其他目录授权、潜在冲突、临时实现与替换、验证结果、提交及合入状态。没有 UI 接入动作时写无。
