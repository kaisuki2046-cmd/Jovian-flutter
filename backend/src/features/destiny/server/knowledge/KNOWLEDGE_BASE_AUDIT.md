# 命理资料库现状审计

扩建基线为本工作树现有的 3,000 条规则，其中性格 2,976 条，事件 24 条。现有合成测试使用 168 份盘。事件层五主题的覆盖分别为综合 28、事业 5、爱情 5、学业 10、财富 20。首批扩建优先补充有明确原文条件的事件素材和能覆盖更多盘面的行为素材。

| 体系 | 请求现有事实 | 计算与适用边界 |
| --- | --- | --- |
| 八字 | `pillar`、`branch`、`stem_ten_god`、`hidden_ten_god`、`shen_sha` | 四柱和支来自排盘。十神、藏干的十神和神煞由计算口径推导。报告请求没有完整旺衰、用神、流年或大运事实。 |
| 紫微 | `palace_branch`、`palace_star` | 宫位与落星来自 iztro。本命星使用引擎值 `origin`。包中还定义 `decadal`、`yearly`、`monthly`、`daily`、`hourly`，报告当前只送本命盘。对宫和三方可根据宫支距离推导。 |
| 西占 | `planet_sign`、`planet_house`、`aspect` | Astronomy Engine 算天体位置，项目计算热带黄道、整宫制及五种主要相位，统一容许度 6°。报告旧请求省略实际 orb。 |

原规则有 `input.required` 和 `input.mustBeAbsent`，构建时编码为关键词，SQLite 通过完整关键词判断命中。关键词能区分位置和取值，无法原生表达备选组和数值边界。事实格式与盘面口径由 `catalog.mjs` 和 `charts.ts` 定义。规则种子以 MJS 编写，SQLite 是可重建的缓存。

旧规则的 `id`、`input`、`source`、`entry.reading`、`reference.basis` 和 `reference.limit` 作为兼容基线。报告仍以三术本命为输入，以综合、事业、爱情、学业、财富的双层结构组织结果。反馈涉及账号或 UI 时由各归属模块继续处理。

## 首批试点回归

以下为同一组 168 份合成出生资料运行实际排盘后，至少有一条规则进入主题素材的样盘数。

| 事件主题 | 扩建前 | 扩建后 |
| --- | ---: | ---: |
| 综合 | 28 | 40 |
| 事业 | 5 | 19 |
| 爱情 | 5 | 9 |
| 学业 | 10 | 10 |
| 财富 | 20 | 25 |

性格层扩建后分别覆盖综合 168 份、事业 164 份、爱情 152 份、学业 155 份、财富 155 份。事件层优先补充爱情、学业等低覆盖主题。此处统计的是规则素材覆盖。

## 第二批事件回归

从同一组取出出生时刻完整的 144 份样盘，统计各主题至少命中一条事件规则的份数。

| 事件主题 | 第二批前 | 第二批后 |
| --- | ---: | ---: |
| 综合 | 40 | 80 |
| 事业 | 18 | 32 |
| 爱情 | 8 | 60 |
| 学业 | 10 | 60 |
| 财富 | 24 | 58 |

至少命中一个事件主题的样盘从 80 份增至 143 份。五个事件主题同时命中的样盘仍为 0 份。事业的单主题事件覆盖在本批后最低，为 32/144。
