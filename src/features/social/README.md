# 社交

底栏「消息」右上角的「找用户」支持输入完整 UID 或昵称。从用户主页返回后保留搜索词并重新检查结果可见性。「新增粉丝」在消息标签内打开，查看通知中的用户主页后返回提醒列表，再返回消息首页。关注和粉丝列表从个人中心进入。在搜索结果打开自己的主页时，可以直接进入「编辑资料」。

个人中心的关注、粉丝计数与列表来自账户服务的 `/social/` 接口。公开 UID 是唯一的 8 位数字，可在个人中心和用户主页长按复制。其他会员开启「隐私设置 → 社交隐私」的搜索后才可被找到，按昵称搜索还要求对方公开昵称。新注册和改名不能使用已占用的昵称。历史同名结果按 UID 区分。关注和粉丝列表仅本人可见，主页和列表共用关注、回关、已关注和互相关注状态。拉黑解除双向关注，并阻止双方搜索、查看和关注。

消息首页不再加载本地演示会话、联系人、群聊或模拟消息。旧演示缓存未在升级时删除，账号注销仍清理当前设备上归属于该账号的缓存。

### 提醒与举报

- `GET /social/notifications/summary` 获取未读数和当前账号的举报处理权限。`GET /social/notifications?before=...` 按时间分页。`POST /social/notifications/read` 传 `{ id }` 标记单条，或传 `{ all: true }` 标记全部。
- 新关注和提醒由同一 SQLite 事务写入，历史关注不补发。一对账号同一方向最多出现一次提醒。拉黑后相关提醒从列表和未读数清除，仅保留去重所需的账号对，时间清零。注销时外键删除关联行。只有按当前权限可见的资料才展示主页链接。
- `POST /social/reports` 返回已有或新建回执，`GET /social/reports?before=...` 仅返回当前账号的举报状态和结论。`GET /social/moderation/reports` 查看待处理队列，`POST` 同一路径提交 `{ id, status, conclusion }`。结论状态为 `resolved` 或 `dismissed`。
- 由账户服务端的 `APP_SOCIAL_MODERATOR_IDS` 配置授权运营账号的内部 UUID，逗号分隔，空值不开放处理。运营账号不能处理自己提交或针对自己的举报。数据库记录结案人员、时间和结论，只有结论和时间向举报者展示。

服务端公开入口为 `server-entry.mjs`，由账户 HTTP 服务传入当前会员、限流和允许公开的资料字段。关系、黑名单、提醒和举报由社交模块在账户 SQLite 中维护，关联用户注销时删除相关记录。现阶段不做自动处罚，处理结论和上线留存规则由运营方确认。

> **跨板块协作**　其他板块的代码可以阅读和参考，可通过对方明确开放的入口或公共 UI 复用能力。需要修改认领范围外的文件时，包括其他板块的代码、业务页面和说明文档，须先向用户说明具体文件、原因和影响，取得明确授权后再修改。

## 协作约束 v1.2

本目录归 `src/features/social/` 管理；默认只改认领范围及本任务相关的 `src/ui/`。业务模块之间不能相互改文件，修改其他目录前 Codex 必须先向用户询问具体范围和影响，获得明确授权后再做。独立认领更小子目录时按更小范围执行。

业务目标采用 `model/`（数据）、`view/`（具体 UI）、`control/`（功能），现有文件按后续任务渐进整理，不表示已迁移。业务请求仍留在本模块 requests；公共 UI 只接收数据、状态和回调。

按 MVP 验收逐步迭代。公共 UI 的破坏性接口或全局风格变更先向用户确认；提交只包含本轮范围，保留并行改动，结束时列出实际目录、共享组件影响和验证。详细规则见 [本目录开工说明](AGENTS.md)、[协作协议](../../../COLLABORATION.md) 与 [框架图](../../../FRAMEWORK.md)。
