# 八字本命计算口径

[基线审计](BAZI_CALCULATION_LAYER_AUDIT.md) · [完整输出 JSON](bazi-analysis.example.json)

示例使用 1973 年 10 月 13 日 04:19 北京的虚构出生资料。既有引擎排出癸丑、壬戌、壬午、壬寅。完整输入时，命理计算在原始八字盘上附加 `analysis`，版本为 `natal-l1-l2-v2`。报告服务使用本命事实匹配资料，计算结果不整包发送模型。

| 模块 | 产出与口径 |
| --- | --- |
| L1 柱位与日主 | 每柱的干支 ID、阴阳、五行、天干十神、藏干十神、神煞及其来源柱。以日干为十神参照，日干本身记作日主。 |
| L1 藏干 | 复用引擎的藏干与十神映射。按规范顺序标记本气、中气、余气。其中巳支在 L1 采用丙、戊、庚，旧字段保留引擎顺序。L1 保存次序，L2 按独立的计分口径使用主、中、余气。 |
| L1 十神索引与五行 | 十种十神各列透出及藏干的位置和次数。五行分别统计四个天干、四个地支自身和全部藏干，并提供每柱计数、全局出现项。三类计数各有独立口径。 |
| L1 月令 | 以月支和本气五行记录月令，寅卯辰为春、巳午未为夏、申酉戌为秋、亥子丑为冬。提供月支五行与各五行的同类、生克关系。 |
| L2 位置结构 | 日坐取日柱地支的实际藏干，透干取年、月、时干。根气记录藏干与日主同干或同五行的柱位。 |
| L2 十神组合 | 两组十神实际存在且满足生克关系时列为候选。双方分别透干或出现在月令本气时记为「具备结构条件」，否则记为「仅见组合线索」。记录双方柱位、干支、透藏位置和实际配对。 |
| L2 干支关系 | 查六合、六冲、害、破、子卯刑、自刑、三合、三会与三刑。三支组缺一支时记录缺项。地支合局与六冲共享柱位时记为「合局见冲」，与刑、害、破共享柱位时记为「关系并见」，同时保留两条关系。天干五合在干相邻、月支同化神五行、有地支藏根、无争合且月支及参与支无六冲时支持合化候选。 |
| L2 辅助 | 计算四柱纳音、同柱神煞组合、日时干支关系。不再计算或输出六亲分组信号。 |

### 旺衰、格局和用神

以下权重、门槛和筛选条件是项目 v2 的可重复计算口径。古籍提供月令、生克、寒暖和通关的概念出处。

| 方法 | 条件与结果 |
| --- | --- |
| 五行与十神强度 | 年、月、时天干各 4 点，藏干本气、中气、余气分别 3、2、1 点，月支藏干基础点数加倍。分值再乘以相对于月支本气的旺、相、休、囚、死系数 5、4、3、2、1。日干作为参照，地支通过藏干记分。五行和十神均从同一贡献明细聚合。 |
| 日主旺衰 | 将同类与生扶日主的五行分数相加，占总分 ≥55% 为偏强，≤45% 为偏弱，其余为相对均衡。结果同时记录月令关系、支持分与总分。 |
| 月令格局 | 月支一般取本气，辰戌丑未遇月藏透干时按藏干顺序优先取透出者。按所取十神列格局候选，并按对应十神结构记录配合或干扰。另筛专旺、从势、化气候选。专旺要求扶助占比至少 80%，且至少三支本气与日主同五行。从势要求扶助占比最多 15%，且藏干无同五行根。化气要求涉及日干的五合符合合化候选条件。 |
| 月令取用、扶抑 | 月令取用列所取藏干的五行。扶抑在偏弱时列同类与生扶，偏强时列泄、耗、克，均衡时不触发。 |
| 调候 | 冬且水分大于火分判偏寒，夏且火分大于水分判偏热。未戌且火大于水判偏燥，辰丑且水大于火判偏湿。偏寒或偏湿列火，偏热或偏燥列水。 |
| 病药 | 分数最高的单行占总分至少 40% 时记录偏聚，列克制该行的五行候选。 |
| 通关 | 两个相克五行各占至少 20% 时，列能连续相生衔接两方的五行，并记录相克双方的分数。 |

概念出处见 [《子平真诠》论用神及成败救应](https://upload.wikimedia.org/wikipedia/commons/f/fe/NLC416-11jh010455-35296_%E5%AD%90%E5%B9%B3%E7%9C%9F%E8%A9%AE.pdf)、[《滴天髓阐微》衰旺、通关、寒暖与燥湿](https://luckclub.cn/pdf/bazi/007.pdf)及 [《三命通会》论十干化气](https://zh.wikisource.org/zh-hans/%E4%B8%89%E5%91%BD%E9%80%9A%E6%9C%83_%28%E5%9B%9B%E5%BA%AB%E5%85%A8%E6%9B%B8%E6%9C%AC%29/%E5%8D%B702)。

出生时刻不完整时保留既有多情景盘面及共有事实。存在冲突或缺项的四柱不能构成完整八字分析，也不能支持模型补充。

模型以“算命大师”角色接收已确认盘面事实的中文描述，以及资料库实际命中的书籍出处与原文、命中条件及现代释义，均为精简文本。四柱和 L1/L2 不以完整 JSON 注入 Prompt。模型自行选择依据并组织性格和事件解读，服务端直接返回模型正文。

完整命盘在客户端排历并分析一次，分析随原始盘面可存档。资料检索按已确认的结构化事实计算必要的条件，不接收客户端自填的分析结构或出生时间戳。后续 Claim 可以按需接入已有计算结果；盘面事实和已命中条件共用中文转换，传给模型的是自然语言描述。

计算和报告回归由 `control/bazi-analysis.test.mjs`、`reading.test.mjs` 和 `server/report.test.mjs` 覆盖。报告接口测试使用模拟模型响应。
