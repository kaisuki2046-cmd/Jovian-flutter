# 登录与会话

- **职责**：处理注册、登录及会话的建立、校验和结束。
- **可能输入**：注册资料、登录凭据或会话凭证。
- **预期产出**：认证状态、经校验的当前用户身份或会话处理结果。

注册页用同一个输入框识别手机号和邮箱。账户服务和网页来源都在本机回环地址且处于非生产环境时，可填写昵称和至少八字符的密码直接注册。注册后用相应的手机号或邮箱加密码登录。正式环境使用邮箱验证码注册，输手机号则进入短信验证流程。浏览器使用 HttpOnly Cookie，移动端使用 SecureStore 保存令牌。会话在服务端七天后过期，改密后撤销其他会话。

验证码通过后，已绑定号码登录原账户，未绑定号码自动创建手机号账户。邮箱账户在账户与安全中绑定或换绑，需要账户密码和新号验证码。手机号账户换绑需要原号和新号的验证码。每个号码只可绑定一个账户。换绑后旧号与原账户解除关联，其他已登录会话失效。验证码五分钟有效、一次性使用，并限制重发和校验次数。

短信验证码、微信或 QQ 首次创建账户后显示「设置昵称」。保存时由账户服务校验当前账号和昵称唯一性，在同一笔更新里写入昵称并清除待设置状态。关闭应用或再次登录也会继续提示，直到保存成功。已在注册表单填写昵称的账号按原流程进入应用。

本机免码注册的手机号在验证前仅用于密码登录。要启用短信登录和找回密码，需在账户与安全中凭当前密码和短信验证码绑定手机号。免码注册的邮箱也仅用于密码登录。

已设置密码的账户可通过邮箱或绑定手机号使用密码登录。手机号账户可验证绑定号码后设置首个密码，后续改密需要当前密码。

已绑定手机号的账户还可从登录页用独立恢复验证码重置密码。恢复用途与登录及换绑验证码隔离，重置后撤销现有会话。邮箱找回邮件尚未接入。登录页临时 AuthSwitch 位于 view/components/，公共 UI 共建跟踪在上级 UI-REQUESTS.md。

认证页面位于 `view/`，表单及会话流程位于 `control/`，客户端令牌读写和服务端凭据模型位于 `model/`。服务端认证由 [server-auth.mjs](control/server-auth.mjs) 编排，HTTP 接口与提供商配置从原账户服务入口接入。

## 本机虚拟服务商

重启账户服务后会尝试加载与 app 仓库并列的 `virtual-auth-provider/provider.mjs`。回环开发环境下，模拟发送的验证码写入该目录的 `inbox/`，页面提示读取最新 TXT。通过邮箱验证码注册时必须提交同一邮箱、验证码及对应挑战编号。验证码五分钟有效，一次性使用。

登录页的微信和 QQ 按钮各使用一个固定的本机测试身份，首次使用创建账户，之后恢复同一账户。两个渠道独立，不按邮箱或昵称合并。模拟账户可使用个人资料及退出登录，手机号绑定和密码设置留待第三方账户绑定流程交付。

服务商缺失或调用失败时，依赖该服务的请求返回 HTTP 503 和 `AUTH_PROVIDER_UNAVAILABLE`。已存在账户的密码登录和会话恢复照常可用。`APP_PHONE_CODES=off` 关闭短信流程。虚拟服务商仅在非生产的回环账户服务及回环网页来源下加载。

## 提供商接入约定

`server/auth-provider.mjs` 定义账户服务端注入的适配接口。真实邮件或短信提供商实现 `deliverCode({ channel, recipient, purpose, code, expiresIn })`，渠道为 email 或 sms。交付成功后结束调用，交付失败时抛错。模拟交付返回 `{ delivery: 'local-inbox' }`，页面据此显示本机收件箱提示。

正式部署使用 `NODE_ENV=production`，注册页通过 `GET /account/auth/capabilities` 的 `emailRegistrationAvailable` 和 `phoneCodesAvailable` 开放可用渠道。既有账户仍可使用密码登录。生产禁用虚拟服务商和免码注册。

- 邮箱在服务端设置 `APP_EMAIL_CODE_ADAPTER`，指向导出 `deliverCode` 的本地模块。供应商和发件域名确定后部署适配器。服务端不会把适配器返回的调试字段发给客户端。
- 腾讯云为暂定短信方案。在服务端安装官方 `tencentcloud-sdk-nodejs-sms`，设置 `APP_PHONE_CODES=tencent`，再配置 `APP_TENCENT_SMS_SECRET_ID`、`APP_TENCENT_SMS_SECRET_KEY`、`APP_TENCENT_SMS_REGION`、`APP_TENCENT_SMS_SDK_APP_ID`、`APP_TENCENT_SMS_SIGN_NAME` 和 `APP_TENCENT_SMS_TEMPLATE_ID`。模板使用一个六位验证码参数。账户服务检查接收号码和 `SendStatusSet` 的发送状态后才生成可用挑战，校验、有效期、用途隔离和限流继续由账户服务处理。[腾讯云 Node.js SDK](https://github.com/TencentCloud/tencentcloud-sdk-nodejs) · [短信发送接口](https://cloud.tencent.com/document/product/382/55981)

微信和 QQ 适配器实现 `exchangeSocial({ provider, authorizationCode })`，在服务端完成授权码验证与交换，再返回 `{ subject, displayName }`。无效证明返回空值，服务异常抛错。真实适配器须要求平台授权证明，并使用独立于 local 的身份命名空间。客户端请求入口已接受授权码，正式接入时由平台授权流程取得它。

> **跨板块协作**　其他板块的代码可以阅读和参考，可通过对方明确开放的入口或公共 UI 复用能力。需要修改认领范围外的文件时，包括其他板块的代码、业务页面和说明文档，须先向用户说明具体文件、原因和影响，取得明确授权后再修改。

## 协作约束 v1.2

本目录归 `src/features/account/auth/` 管理；默认只改认领范围及本任务相关的 `src/ui/`。业务模块之间不能相互改文件，修改其他目录前 Codex 必须先向用户询问具体范围和影响，获得明确授权后再做。独立认领更小子目录时按更小范围执行。

业务目标采用 `model/`（数据）、`view/`（具体 UI）、`control/`（功能），现有文件按后续任务渐进整理，不表示已迁移。业务请求仍留在本模块 requests；公共 UI 只接收数据、状态和回调。

按 MVP 验收逐步迭代。公共 UI 的破坏性接口或全局风格变更先向用户确认；提交只包含本轮范围，保留并行改动，结束时列出实际目录、共享组件影响和验证。详细规则见 [本目录开工说明](AGENTS.md)、[协作协议](../../../../COLLABORATION.md) 与 [框架图](../../../../FRAMEWORK.md)。
