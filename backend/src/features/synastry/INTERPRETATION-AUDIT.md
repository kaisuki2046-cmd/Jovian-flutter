本文保留早期版本的实现记录。当前资料来源及历史文件恢复方式见[旧库迁移](server/knowledge/MIGRATION.md)。

## 基线与迁移

当前工作树基线为 `codex/synastry/relationship-evidence` 的 `eff1751`，本轮沿用工作树中的合盘实现。实施规范引用的独立《玄玄合盘解读规则清单.md》未在工作树或下载目录找到。迁移使用仓库里的 `model/interpretation-knowledge.json`，其版本、三术条目数和五个来源 ID 与规范相符。

原文件保留，SHA-256 为 `91bfcf57c626485aa1c8b0e97ed8b3be17f4fc8b75a65874066d43a3b705bda4`。回归测试逐条比对原 ID、条件、传统依据、来源、版本、限制、极性、场景和草稿状态。迁移使用独立 JSON，沿用 Expo 的静态打包。

| 内容 | 存储 | 当前规模 |
| --- | --- | --- |
| 原子知识与来源索引 | `model/interpretation-atoms.json` | 31 条原子、5 项来源 |
| 关系变体 | `model/interpretation-variants.json` | 34 条，亲情 4、友情 3、爱情 16、合作 11 |

现有原子、变体和组合均为草稿。种子条目原来的关系限制保留在原子上并由变体继承。每个变体使用稳定的 `knowledgeId:relationshipType` 作为迁移 ID，后续同一场景可有独立 ID 的其他主题或极性变体。原子、变体和组合分别审核及版本化。

## 事实字段与覆盖

现有三术计算输出 `ComparisonSection.evidence`。[事实适配器](control/interpretation-fact-adapter.ts)继续为实例生成稳定 ID。[字段注册表](model/interpretation-facts.ts)约束条件字段。八字保留双方柱位、原局与跨盘组合来源；紫微保留本命星曜、三方四正及实际飞化的来源和去向；西占保留有序天体角色、实际角距、容许度和盘面规则配置。

| 体系 | 种子原子 | 有候选条目的事实类型 | 注册事实类型 |
| --- | ---: | ---: | ---: |
| 八字 | 10 | 10 | 13 |
| 紫微 | 8 | 4 | 4 |
| 西占 | 13 | 7 | 9 |
| 合计 | 31 | 21 | 26 |

覆盖按事实类型统计，同一类型下具体参数组合的覆盖更小。已审核原子、变体及组合均为 0 条。科目缺口包括八字天干冲、日干相对十神和神煞同支对照，以及西占星座对照和同名角距。紫微宫干飞化的实际数据仍需命理及账户接线，见[临时交接单](INTEGRATION-HANDOFF.md)。

逐条检查时需要注意三点。

- 双方日支六合与六冲使用同一对日支，在当前事实定义下无法同时命中。组合库选择真实可并存的证据，八字跨柱互动仍由各自事实支持。
- 紫微本命四化与宫干飞化使用不同事实。飞化的原盘落点和对方同支宫位分别追溯。
- 西占保留 A 金星与 B 火星、A 火星与 B 金星两条有序模式。计算层可以产生双向日月天体排列，种子 `WEST-SUN-MOON-TRINE` 仅有 A 太阳和 B 月亮的场景解释。其他排列保留为事实。

## 检索、组合和表达

[知识仓库与检索](control/interpretation.ts)依次检查精确实例 ID、结构化模式和事实类型，再检查流派、排盘版本、关系、主题、成立条件与排除条件。别名入口供审核检索使用。流派各自保留规则和证据，冲突可并列呈现。例如水星四分相在友情场景成立但仍为草稿时，轨迹包含 `factTypeId=western:western-cross-aspect`、`variantId=WEST-MERCURY-SQUARE:friendship` 和 `pending_review`。

[组合匹配](control/interpretation-combinations.ts)按声明的原子 ID 查找同一关系下的已审核变体，检查前置事实齐全及方向条件，只追加带证据引用的组合解释。同源组合仍保留每条原始证据。跨术数同时有日支六合与月亮对分时，若原子、对应场景和组合均经审核，可输出 `contradicts`，分别引用原有正向与负向证据。

[证据包与输出校验](control/interpretation-context.ts)提供一个关系的已审核命中和组合。证据可追溯到 `evidenceId`、`factId`、`knowledgeId`、`variantId`、来源以及版本。证据包省略完整盘面和快照标识，关系报告在本地仍保留双方快照引用。每条生成判断须带 `evidenceIds` 与匹配的 `factIds`，引用组合时须覆盖组合的全部证据。输出校验会拦截越界关系、无效引用和遗漏负向依据。模型生成仍待接线，文本语义真实性需要额外审核。

报告携带事实 schema、来源索引、知识库和组合规则版本，证据包另带 Prompt 版本。当前报告仅在页面内存生成，历史归档接口仍待集成。发布新内容时递增对应条目和清单版本，合入后交接归档时保留旧报告原有版本及 ID。

## 采集、审核和发布

1. 从`model/interpretation-research.json`选定实际事实及关系类型，记录需要解决的流派、柱位、宫位或容许度问题。
2. 登记标题、作者、版本、章节、位置、流派及访问日期。单独核对代码许可和文本、数据的使用授权。
3. 将独立整理的定义、触发条件、适用关系与例外记录到研究笔记。不同流派按 `schoolId` 分开维护。
4. 将可由事实字段核验的规则登记为原子，将场景措辞和独立适用条件登记为变体。组合仅在来源清楚且前置证据可同时命中时录入。新增条目初始为 `draft`。
5. 增加命中、反例和临界用例后提交审核。批准时分别记录人工审核者、日期、依据或决议链接，校验可用于派生的来源；发布时更新版本。

| 来源 | 现有使用边界 |
| --- | --- |
| `SOURCE-L0` | 项目内计算依据，可追溯事实结构；场景含义仍需专家核对 |
| `SOURCE-PRODUCT` | 规范出处元数据 |
| `SOURCE-BAZI-CLASSIC` | 古籍出处元数据；现代注释、点校及整理版须另核许可 |
| `SOURCE-IZTRO-TERMS` | 术语及计算口径出处元数据；代码许可与解释文案权限分别核对 |
| `SOURCE-TRADITIONAL-RULERS` | 传统守护星出处元数据；翻译及现代注释须另核许可 |

规范列出的其他开源数据集和解释文本尚未导入。新增资料在确认版本、文本授权、关系适用性后再入库。

回归入口为 `npm test -- src/features/synastry`。并行或发布前运行 `npm run typecheck`、`npm run check:boundaries` 和 `npm test`。既有底栏仍待路由负责人接线。
